# 短剧开局决策路由

替他做决定，给结论，立刻交接。产出 = 第五节「回答六样」。

```
① 抽信号（从他的话里读，读不到用默认值）
② 查第 2.2 节决策总表，命中即停
③ 给第五节「回答六样」
④ 关键分叉拿不准才问（一轮最多一个）
⑤ 立刻交接（第四节）
```

能推的自己推；结尾补一句「如果你是 X，说一声我换方案」。

## 一、一条片子 6 段

| 段 | 干什么 |
|---|---|
| ① 选题 | 讲什么、给谁看（只能人定） |
| ② 剧本 | 谁、要什么、怎么翻 |
| ③ 资产 | 几个人 / 场景 / 道具 |
| ④ 分镜 | 每镜一句画面 + 一句动作（字段与写法以途视 CLI 取回的模板规则为准） |
| ⑤ 出片 | 出图 → 出视频 → 配音配乐 |
| ⑥ 后期 | 剪辑、音量、字幕 |

⑤ 段工具选型不展开；① 段由用户定；⑥ 段开工前说清谁做。各段承包见第 2.2 节。

## 二、决策

### 2.1 六个信号

从他的话里读；读不到用默认值。

| 信号 | 取值 | 默认 |
|---|---|---|
| 原料 | 原著长篇 / 原著短篇 / 现成剧本 / 已有分镜图素材 / 只有想法 | 只有想法 |
| 出口 | 算法分发 / 人工评审 / 客户合规交付 / 自己玩 / 只要文本 | 算法分发 |
| 规模 | ≤90 秒 / 1–5 分钟 / 20–80 集连载 / 90 分钟长片·季播 / MV | ≤90 秒 |
| 时效 | 热点快反 / 常规 | 常规 |
| 内容形式 | 纯旁白 / 纯对白 / 混合 | 不明就问 |
| 容错 | 高 / 中 / 低 | 中 |

他还没说要做什么 → 只问一句「这条片子是什么、给谁看」。有了这句话之后，只在原料 / 出口 / 规模 / 内容形式不明时才问（一次一个）——**尤其内容形式：用户没指定时必须问「纯旁白 / 纯对白 / 混合」，不许默认旁白**。定下来的内容形式，写进 ②③④ 剧本/分镜专家的开工约束，并随 ⑤ 的接口一（逐镜提示词）传给途视——对白/旁白按它写，旁白不入画面、对白进 VideoPrompt 遵循途视分镜模板规则。

组合标签：A 改编量产 · B 原创全工程 · C 单篇速出 · D 素材直出 · F 专家直用；E 拼链（② `short-drama-write` + ③④ shuohao 库）只在已跑通一条、明确想更好时才提。

- 专家列有名字 = 那段先切成那位专家，切成功再动手；切不了就停住等他切。
- 技能列写的是现装技能 → 没装就先按第 3.3 节装齐，装完再开工；装不上就降到默认链路（`tushi-cli-creation` + 专家）。
- 只有技能、专家列是「—」的行 → 技能是唯一路径，自己加载自己干。
- ⑤ 段出片走 **tushi-cli-creation**，上游交接口一（逐镜提示词 + 参考图清单）；它随默认包走，在 `skills\` 下。
- 点错速查：有完整剧本 → 「AI视频创作团队」不编剧；长片 → 「短视频编剧」不接；抖音 → 山音不接；⑥ 段 `tushi-cli-creation` 只出素材。

### 2.3 兜底

| 情况 | 怎么办 |
|---|---|
| 信号矛盾（又要参赛又要算法分发） | **以出口为准**；赛事多要求未公开发表 → 已投 / 待评的成片先别发平台，换素材或换选题 |
| 什么都没有 | 照第 2.1 节走，给结论前先出 **3 个选题候选** 并说明取舍，由用户定 |
| 真判断不了 | 混合链：① 专家选题 → ②③④ `short-drama-*` → ⑤ `tushi-cli-creation` → ⑥ `jianying-editor` |
| 只想「别犯错、赶紧开始」 | AI视频脚本创作专家 + `tushi-cli-creation` + `jianying-editor` |
| 参赛 / 交付，容错中以上 | ⑥ 段末尾加一次技术体检（分辨率 / 时长 / 音量 / 字幕） |

### 2.4 什么时候换

| 现象 | 动作 |
|---|---|
| 剧本改 3 轮还不满意 | 上游换 `short-drama-write` 或「短视频编剧」 |
| 出现「写错但提示成功」 | 加 shuohao 库断言门，挂在写入之后、导出之前 |
| 完播率不好 | 换「短视频编剧」重做**前 3 秒** |
| 多集、角色每集变形 | 换「短剧创作专家团」+ 跨集复用脸 |
| 要今天的事今天发 | 换「AI视频创作团队」 |
| 逐镜质量忽好忽坏 | 回 ④ 段对齐提示词，再重跑生成 |

## 三、接口 · 专家 · 技能

### 3.1 交接接口

- **接口一**（交给生产）：逐镜提示词 + 参考图清单。
- **接口二**（交给后期）：素材片段。

答组合必带接口。只有想法时：做**一条** → C；做**系列 / 多集** → B。E 只在「已跑通一条 + 想更好」时提。

### 3.2 这 8 位专家：三层名字

- **市场名** = **菜单里显示的条目名**（输入框「+」→ 专家，或左侧「专家」页）= `plugin.json` 的 `profession.zh`，`search_plugins` 也只认它 → **卡片标题、入口点名、换代指路，三处都只报它**；
- **显示名**（角色）：切进去之后的人设，开工后按它说话；内部行文可用简称（大壮／苍何／跳跃视界），**别拿它让用户去菜单里找**；
- **slug**：包名，本机目录与 marketplace.json 用它。

| 市场名（菜单条目名 = 在线检索词） | slug | 显示名（角色，切完才生效） |
|---|---|---|
| **短视频编剧** | `dazhuang-short-video-script` | 大壮·短视频脚本专家 |
| **AI视频脚本创作专家** | `ai-video-script` | 鹏城信息AI专家 |
| **内容创作专家团** | `ai-content-creator-team` | 内容创作专家团 |
| **AI视频创作团队** | `video-gen-team` | 苍何视频生成团队 |
| **短剧创作专家团** | `tiaoyue-screenplay-team` | 跳跃视界 |

- 发卡前读专长：先读 `search_plugins` 返回的 `description`，读不到再读 `~/.workbuddy/plugins/marketplaces/experts/plugins/<slug>/.codebuddy-plugin/plugin.json` 的 `displayDescription.zh`。
- 一个会话只挂一位专家；点到 2 位以上按段顺序切：这段归谁先切成谁，切成功再开工，做完这段再切下一位。
- 只从这 8 位里选，认本表 slug（市场有同名条目）。
- 专家管 ②③④ 的内容与判断，产出按 **接口一** 交给 tushi-cli-creation 出片。

#### 怎么找到它、弹窗让用户装上

这 8 位在本机市场与在线市场都有；在线索引名 = 上表「市场名」。

1. **定 slug → 读 plugin.json**：拿 `profession.zh`（市场名）+ `displayDescription.zh`（专长一句话）。
2. **搜在线市场**：`search_plugins`(`type: "expert"`)，检索词用市场名（搜大壮写「短视频编剧」）；可补一句这段要干什么。接口只回部分候选，没搜到换关键词再试一次，仍无走第 4 步。
3. **弹卡**：`suggest_plugin_install` 一次放 1–3 个候选，`pluginId` 填本会话 `search_plugins` 返回的 id。点完装上并启用，身份即时换成它；选项标题 = 市场名｜专长一句话。
4. **入口切换**：输入框「+」→ 专家（或左侧「专家」页）→ 搜索框输 **市场名** → 点它。菜单里只有市场名（如「短剧创作专家团」），**别报显示名让他找**。
5. **卡被收起或超时**：同批候选立刻再发，发到他点为止。切成与否看上下文有没有 `<current-expert>` / `<expert_selection>`。

## 四、给完结论就交接

结论说完 = 立刻动作。

**⓿ 先确认需求**：他还没说要做什么 → 只问一句「这条片子是什么、给谁看」；给了需求 → 扫 `作品\` 找同主题前序文件（决策卡 / 分镜脚本 / 开工单），找到先确认「已有《X》的 ①②，接着做吗」，点头才续做，主题对不上从零开始；已交付的段不重做。

**⓿-1 先取模板规则再动笔（硬顺序）**：任何写 ④ 分镜（乃至 ②③④ 需要字段规范的工序）之前，**先经 `tushi-cli-creation` 拿途视模板规则**，不许专家凭空写分镜、不许拖到 ⑤ 出片才第一次取——①先 `template list` 预热 → ②`template get` 取对应用户所选生成模式的**生成分镜模板**（contentJson 字段结构 + contentDes 写作规范：`dialogueName`/`dialogue`/`imagePrompt`/`videoPrompt`/`time`、枚举、镜间连贯、爆款结构、时长字数 1s≈4字）＋ CLI 导演模板（1100）→ ③把这两份规则（含 2.1 定的内容形式：纯旁白/纯对白/混合）**随开工约束交给该段剧本/分镜专家**，按它写；④专业交的 ④ 分镜到 ⑤ 出片时仍按模板规则回校验。

**① 技能**：当场加载并做完第一件具体的事；没装就先按第 3.3 节装齐再加载；这件事归专家就先走 ② 切身份。

**② 专家**：先切成那位专家的身份，切成功才开工；停住等他点，不设倒计时。
- 身份看上下文 `<expert_selection>` / `<current-expert>`，有 = 已切成，直接按它人设开工。
- 提问卡（不超时）：只在第 2.2 节没点名专家时用；选项给第 3.2 节里该管的 1–4 位 +「先不用专家，你直接做」；选项标题 = 市场名｜专长一句话。
- 专家卡：`search_plugins` 取候选 → `suggest_plugin_install` 并排 1–3 个，`pluginId` 用本会话检索返回的 id；卡被收起就同批再发，发到他点为止。
- 卡里放不出目标本人时，放最接近的并标「市场在线候选」，同时给他入口点名：输入框「+」→ 专家 → 按**市场名**搜（如「短剧创作专家团」）。
- 一段做完要换下一位 → 入口按**市场名**点它。

**③ 交接物**：说清交接口一 / 接口二，他回来交什么。

**④ 交接完退场**：把质量承诺留给下游。

## 五、回答六样

一句话结论（哪套组合、为什么）｜六段谁承包（专家**市场名** + 技能名）｜第一件事（具体动作）｜交接物（产出什么、拿去干什么）｜缺什么直接装上 + 一个坑｜交接动作（加载了什么技能、卡发了没有、身份切成了谁）。

他只问什么就讲什么，不一次倒完全流程。

## 六、常识

通用工具做不到的 5 项：剧作深度、确定性质量门、平台算法适配、整片级后期、实时热点采集 —— 分别由 `screenwriting-master`（山音）、shuohao 库断言门、「短视频编剧」、「ChatCut 视频剪辑师」、「AI视频创作团队」补。

黑话：「AI 能帮我写剧本吗」= 我能不能什么都不做（能帮，判断还是你的）；「用哪个工具出片好」= 以为出片是难点（差别不大）；「我该装哪个」= 该问组合；「我的角色每集不一样」= 资产没定义（补 ③ 段清单）；「有没有现成的专家」= 想找人干活；「我什么都不知道」= 给兜底方案。
